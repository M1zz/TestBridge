# 클립키보드 테스트 시나리오

TestBridge로 클립키보드(`com.Ysoup.TokenMemo`)를 검사하는 플랜 네 개입니다. 2026-11-11에 클립키보드 5.1.20(50) 최신 커밋을 iPhone 17 Pro Max 시뮬레이터(iOS 26.4)에서 돌려 네 플랜 모두 탐색·동작 스텝이 전부 통과하는 것을 확인했습니다. 실패로 표시되는 것은 HIG 검사(`higAudit`, `failOn: error`)가 실제 위반을 찾았기 때문입니다.

## 실행 순서

| 순서 | 플랜 | 무엇을 보나 | 검사하는 화면 |
|---|---|---|---|
| 1 | `clipkeyboard-hig-tabs` | 탭 네 개가 HIG를 지키는지 | 목록(첫 화면) · 사용 기록 · 설정 · 검색 |
| 2 | `clipkeyboard-create-shortcut` | 단축어를 만들면 시트가 닫히고 첫 화면에 서는지 (기능) + 새 단축어 시트 HIG | 새 단축어 시트 · 단축어가 생긴 첫 화면 |
| 3 | `clipkeyboard-hig-settings-deep` | 설정 하위 화면 여섯 개의 HIG | 키보드 · 단축어 · 화면과 표시 · 내 데이터 · 무료로 쓰는 방법 · 페이월 |
| 4 | `clipkeyboard-keyboard-stage` | 앱 안 키보드 미리보기에서 단축어 키를 누르면 입력창에 들어가는지 (기능) + 키보드 판 HIG | 키보드 미리보기 · 조작 키를 펼친 판 |

4번은 2번이 만든 단축어 `TestBridge 인사`를 키보드에서 누르므로 2번 뒤에 돌립니다.

플랜 이름은 한국어입니다: `클립키보드 · 탭 네 개 HIG 검사`, `클립키보드 · 단축어 만들기`, `클립키보드 · 설정 하위 화면 HIG 검사`, `클립키보드 · 키보드 미리보기에서 단축어 넣기` (파일 이름은 위 표 그대로).

## 돌리는 법

앱에서: 플랜 탭에 네 플랜이 들어 있습니다. 하나를 고르고 ▶(⌘R). 결과는 실행 탭, HIG 결과는 HIG 탭에서 봅니다.

터미널에서:

```zsh
export TESTBRIDGE_RUNNER_PROJECT="$PWD/Runner/TestBridgeRunner.xcodeproj"   # 레포 루트에서
testbridge run Examples/clipkeyboard/clipkeyboard-hig-tabs.json --destination <시뮬레이터 UDID>
```

플랜에는 기기를 박아 두지 않았습니다. 클립키보드가 설치된 시뮬레이터를 `--destination`으로 넘기세요.

## 실행 인자가 하는 일

클립키보드 자체 UI 테스트(`ClipKeyboardUITests.swift`)가 쓰는 "쓰던 사람" 인자를 그대로 가져왔습니다. 첫 실행 안내, 튜토리얼, 예시 제안, 팁, 피드백 묻기 시트를 끄고 한국어로 고정합니다. 거기에 넷을 보탰습니다.

- `-feedbackNudgeOptOutDate 1762700000` — "혹시 불편한 점이 있으세요?" 알림을 6개월 유예 상태로 둡니다. 이게 없으면 열 번째 실행마다 알림이 떠서 첫 탭이 먹힙니다.
- `-snippetsTabStyle.v1 list` (4번은 `keyboard`) — 첫 탭을 목록으로 고정합니다. 이 인자가 있으면 화면의 키보드/목록 전환 버튼은 듣지 않으므로, 키보드 미리보기를 보려면 인자 자체를 `keyboard`로 줘야 합니다.
- `-blankStart.v1 NO -blankStart.finished.v1 YES` — 새로 깐 기기에서 뜨는 "백지 첫 실행" 온보딩을 끕니다. 없으면 온보딩이 화면 전체를 덮어 아무 스텝도 닿지 않습니다.
- `-userState.showsAllFeatures.v1 YES` — 설정의 "모든 기능 바로 보기"를 켭니다. 단축어가 적은 기기에서는 사용 기록 · 검색 탭이 숨겨지는데, 이 인자가 있으면 기기 상태와 무관하게 탭 네 개가 섭니다.

설정 하위 화면에서 돌아올 때는 뒤로 버튼(`BackButton`)을 누릅니다. iOS 26에서는 이미 선택된 설정 탭을 다시 눌러도 첫 화면으로 돌아가지 않습니다.

## 2026-11-11 HIG 결과 (자동 검출을 검토해 추림)

고쳐야 할 것 — 44×44pt보다 작은 탭 영역(`target-size`)이 대부분입니다.

- 첫 화면: 배너 닫기 × 14×14 · 23×22 · 26×26, 텍스트 링크 "허용하러 가기" 109×20 · "더 이상 보지 않기" 116×20, 카테고리 이름 안내의 "그대로 쓰기" · "이름 바꾸기" 186×40, "단축어 추가" 56×36 (그 안에 라벨 없는 버튼이 겹쳐 있어 `nested-interactive` · `missing-label`도 함께)
- 사용 기록: 기간 선택 "이번 주 / 이번 달 / 전체" 각 133×32, "커피 한 잔 주문할 시간이에요." 364×32
- 새 단축어 시트: "취소" 54×36, "붙여넣기" 104×34, "기존 단축어에서 가져오기" 400×40, "카테고리" 44×20, "스캔해서 글자 넣기" 줄에 라벨 없는 버튼이 겹침
- 페이월: 아래 링크 "복원" 21×14 · "이용약관" 42×14 · "개인정보 처리방침" 87×14 · "7일 무료 체험 시작" 90×14, "모든 기능 비교" 400×26, 요금제 전환 "Plus / Pro" 194×40
- 키보드 미리보기: "보내기" 30×30, 조작 키를 펼쳤을 때 "숫자 판" 32×28

거짓 양성으로 본 것

- 스위치의 `target-size` · `missing-label`(설정 ▸ 키보드 4개, 단축어 1개, 화면과 표시 2개, 내 데이터 1개, 새 단축어 시트 2개): 시스템 스위치는 63×28이 표준이고, SwiftUI `Toggle`은 라벨이 줄 전체에 붙습니다.
- 새 단축어 시트의 "Continue" 224×21: 앱 것이 아니라 시뮬레이터 시스템 키보드의 밀어서 입력 안내입니다.
- 설정 목록의 40pt 행(`list-row-height`): 구역 머리말입니다.
- 키보드 미리보기의 `overlapping-targets`: 그 밑에 깔린 목록 화면 요소가 함께 잡힌 것입니다(아래 "알아 둘 것").

위반이 없던 화면: 검색, 설정 첫 화면, 무료로 쓰는 방법.

지난 검사(11-10) 뒤로 나아진 것: 키보드 판의 카테고리 키와 자판 전환 키가 44×44가 됐습니다.

## 알아 둘 것

- 키보드 미리보기 검사에는 그 밑에 깔린 목록 화면의 배너 버튼(닫기 등)이 함께 잡힙니다. 같은 탭 안에서 목록과 키보드를 겹쳐 두는 구조라 접근성 트리에 둘 다 남기 때문입니다.
- 키보드 익스텐션 자체(다른 앱에서 올라오는 키보드)는 XCUITest가 호스트 앱만 띄우므로 이 플랜으로는 닿지 않습니다. 앱 안 "키보드 미리보기"가 같은 뷰를 쓰므로 그걸로 대신합니다.
- 2번을 여러 번 돌리면 `TestBridge 인사` 단축어가 그만큼 쌓입니다. 검증은 그대로 통과합니다.
- 첫 화면의 카테고리 이름은 기기마다 다릅니다(기본 · 업무 등). 플랜은 카테고리 이름에 기대지 않습니다.
