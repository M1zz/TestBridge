# 클립키보드 테스트 시나리오

TestBridge로 클립키보드(`com.Ysoup.TokenMemo`)를 검사하는 플랜 네 개입니다. 2026-11-10에 iPhone 17 시뮬레이터(iOS 27.0)에서 모두 끝까지 돌아가는 것을 확인했습니다. 탐색·동작 스텝은 전부 통과했고, 실패로 표시되는 것은 HIG 검사(`higAudit`, `failOn: error`)가 실제 위반을 찾았기 때문입니다.

## 실행 순서

| 순서 | 플랜 | 무엇을 보나 | 검사하는 화면 |
|---|---|---|---|
| 1 | `clipkeyboard-hig-tabs` | 탭 네 개가 HIG를 지키는지 | 목록(첫 화면) · 사용 기록 · 설정 · 검색 |
| 2 | `clipkeyboard-create-shortcut` | 단축어를 만들면 시트가 닫히고 첫 화면에 서는지 (기능) + 새 단축어 시트 HIG | 새 단축어 시트 · 단축어가 생긴 첫 화면 |
| 3 | `clipkeyboard-hig-settings-deep` | 설정 하위 화면 다섯 개의 HIG | 키보드 · 단축어 · 화면과 표시 · 앱 정보 · Pro 업그레이드(페이월) |
| 4 | `clipkeyboard-keyboard-stage` | 앱 안 키보드 미리보기에서 단축어 키를 누르면 입력창에 들어가는지 (기능) + 키보드 판 HIG | 키보드 미리보기 · 숫자 판 |

4번은 2번이 만든 단축어 `TestBridge 인사`를 키보드에서 누르므로 2번 뒤에 돌립니다.

## 돌리는 법

앱에서: 플랜 탭에 네 플랜이 들어 있습니다. 하나를 고르고 ▶(⌘R). 결과는 실행 탭, HIG 결과는 HIG 탭에서 봅니다.

터미널에서:

```zsh
export TESTBRIDGE_RUNNER_PROJECT="$PWD/Runner/TestBridgeRunner.xcodeproj"   # 레포 루트에서
testbridge run Examples/clipkeyboard/clipkeyboard-hig-tabs.json
```

`destination.udid`는 지금 부팅된 iPhone 17(`B3935680-…`)로 박혀 있습니다. 다른 기기면 그 줄을 지우고 `--destination`으로 넘기세요.

## 실행 인자가 하는 일

클립키보드 자체 UI 테스트(`ClipKeyboardUITests.swift`)가 쓰는 "쓰던 사람" 인자를 그대로 가져왔습니다. 첫 실행 안내, 튜토리얼, 예시 제안, 팁, 피드백 묻기 시트를 끄고 한국어로 고정합니다. 거기에 두 개를 보탰습니다.

- `-feedbackNudgeOptOutDate 1762700000` — "혹시 불편한 점이 있으세요?" 알림을 6개월 유예 상태로 둡니다. 이게 없으면 열 번째 실행마다 알림이 떠서 첫 탭이 먹힙니다.
- `-snippetsTabStyle.v1 list` (4번은 `keyboard`) — 첫 탭을 목록으로 고정합니다. 이 인자가 있으면 화면의 키보드/목록 전환 버튼은 듣지 않으므로, 키보드 미리보기를 보려면 인자 자체를 `keyboard`로 줘야 합니다.

첫 화면의 "내 것을 저장해보세요" 팝오버는 앱 전용 저장소에 기록되어 인자로 끌 수 없습니다. 그래서 모든 플랜이 제목 `기본`을 한 번 탭하며 시작합니다. 팝오버가 떠 있으면 닫히고, 없으면 아무 일도 없습니다.

## 오늘 나온 HIG 위반 (자동 검출, 중복 제거)

44×44pt보다 작은 탭 영역(`target-size`)이 대부분입니다.

- 첫 화면: 배너 닫기 × 14×14 · 12×12 · 23×22, 텍스트 링크 "허용하러 가기" 108×20 · "더 이상 보지 않기" 116×20, "단축어 추가" 56×36 (그 안에 라벨 없는 버튼이 겹쳐 있어 `nested-interactive`·`missing-label`도 함께)
- 사용 기록: 기간 선택 "전체 / 이번 달 / 이번 주" 각 121×32, "전체 기간 보기" 85×18
- 새 단축어 시트: 라벨 없는 버튼 134×44 세 개(스캔·이미지·붙여넣기 줄로 보임), 라벨 없는 스위치 두 개 63×28 · 61×28, "쓸 때 채우는 칸" 402×40, "카테고리" 46×20, "붙여넣기" 104×34, "취소" 61×36
- 설정 ▸ 키보드, 화면과 표시: 라벨 없는 스위치 63×28
- 페이월: "이전 구매 복원" 97×20, 닫기 30×36
- 키보드 미리보기: 키보드 판 전환 키 "숫자 판"·"단축어로 돌아가기" 32×28, 카테고리 "기본" 42×28, "보내기" 30×30

스위치의 `missing-label`은 SwiftUI `Toggle`에 라벨이 있어도 스위치 요소 자체에 라벨이 안 붙는 경우가 있어, Claude 검토에서 거짓 양성으로 걸러질 수 있습니다.

## 알아 둘 것

- 키보드 미리보기 검사에는 그 밑에 깔린 목록 화면의 배너 버튼(닫기, 허용하러 가기 등)이 함께 잡힙니다. 같은 탭 안에서 목록과 키보드를 겹쳐 두는 구조라 접근성 트리에 둘 다 남기 때문입니다. 키보드 판 자체의 위반은 "숫자 판", "기본", "보내기" 셋입니다.
- 자판(두벌식) 키는 이 사용자 상태에서는 키보드에 없어서(기능 더하기에서 꺼져 있음) 한글 조합 시나리오는 넣지 않았습니다. 켜는 인자를 알면 `clipkeyboard-keyboard-stage`에 `자판` 탭 → `ㅎ ㅏ ㄴ` 스텝을 붙이면 됩니다.
- 키보드 익스텐션 자체(다른 앱에서 올라오는 키보드)는 XCUITest가 호스트 앱만 띄우므로 이 플랜으로는 닿지 않습니다. 앱 안 "키보드 미리보기"가 같은 뷰를 쓰므로 그걸로 대신합니다.
- 2번을 여러 번 돌리면 `TestBridge 인사` 단축어가 그만큼 쌓입니다. 검증은 그대로 통과합니다.
